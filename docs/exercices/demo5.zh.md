## 第一小时：概念与回顾

### 第1节 — 主题判断题

对每个陈述，判断其**真**或**假**并说明理由。

#### A组 — 基础与理念

??? question "第1题 — 复杂度与代码长度"
    代码行数更多的算法解决同一问题时必然比更短的算法慢。

    ??? success "答案"
        **假。** 算法复杂度取决于**操作次数关于输入大小的函数**，而非代码行数。

        示例：插入排序（代码简短）的复杂度为 O(n²)，而归并排序（代码较长）为 O(n log n)。对于大型输入，代码更长的算法反而快得多。

        **经典陷阱：**认为"代码越多 = 越慢"。渐近复杂度优先于代码长度。

??? question "第2题 — 不变量的代价"
    维护一个不变量（例如，保持列表有序）与其带来的收益相比，代价总是可以忽略不计的。

    ??? success "答案"
        **假。** 维护不变量的代价可能非常显著，需要与收益进行权衡。

        示例：有序列表允许 `min()` 在 O(1) 内完成，但每次插入需要 O(n) 来维持顺序。如果插入频繁而查询最小值很少，这个代价是不可接受的。

        **正确的选择取决于主要操作。** 这就是为什么我们比较：

        | 结构 | `insert` | `min` | 何时使用 |
        |------|----------|-------|---------|
        | 无序列表 | O(1) | O(n) | 查询较少 |
        | 有序列表 | O(n) | O(1) | 插入较少 |
        | 堆 | O(log n) | O(1) | 均衡使用 |

??? question "第3题 — 均摊复杂度"
    均摊 O(1) 复杂度保证每个单独的操作都在常数时间内完成。

    ??? success "答案"
        **假。** **均摊** O(1) 复杂度意味着在 n 个操作的长序列中，总代价为 O(n)，因此**平均**每个操作花费 O(1)。

        然而，某些单独操作可能需要 O(n)。例如，`ArrayList.add()`：

        - 大多数添加操作：O(1)
        - 当数组已满时：O(n) 用于扩容和复制

        **经典陷阱：**将均摊复杂度与最坏情况复杂度混淆。均摊是平均值，而非每次操作的保证。

#### B组 — 线性结构

??? question "第4题 — LinkedList 与插入"
    对于有 10,000 个元素且频繁在中间插入的列表，`LinkedList` 的性能总是优于 `ArrayList`。

    ??? success "答案"
        **假。** 这一说法忽略了一个关键代价：**查找插入位置**。

        在中间插入时：

        | 结构 | 查找位置 | 插入 | 总计 |
        |------|---------|------|------|
        | ArrayList | O(1) 按索引 | O(n) 移位 | O(n) |
        | LinkedList | O(n) 遍历 | O(1) 重链接 | O(n) |

        两者都是 O(n)！此外，`ArrayList` 具有更好的**缓存局部性**（内存中元素连续），在实践中通常更快。

        **仅当已有位置引用时，LinkedList 才具有优势**（通过迭代器或位置列表中的位置）。

??? question "第5题 — LinkedList 中 get(i) 的优化"
    在 Java 的 `LinkedList` 中，调用 `list.get(n/2)` 已被优化为从列表中间开始。

    ??? success "答案"
        **假。** Java 根据索引从**开头或末尾**开始优化：

        - 若 `i < size/2`：从开头遍历
        - 若 `i >= size/2`：从末尾遍历

        但**不存在对中间的直接访问**。对于 `get(n/2)`，Java 从某端遍历约 n/2 个元素。

        ```java
        // LinkedList 中 get(i) 的复杂度
        // 最好情况：O(1) 当 i=0 或 i=size-1
        // 最坏情况：O(n/2) = O(n) 当 i≈n/2
        ```

        **经典陷阱：**低估链表中 `get(i)` 的代价。在最坏情况下它始终是 O(n)，绝非 O(1)。

??? question "第6题 — 位置的稳定性"
    在位置列表中，若在某 `Position` 前插入一个元素，该位置将失效。

    ??? success "答案"
        **假。** 这正是位置相对于索引的优势所在！

        - **索引**：若在索引 5 之前插入，原来在索引 5 的元素现在在索引 6。索引 5 指向了另一个元素。

        - **位置**：位置代表结构中一个**稳定**的位置。插入其他元素不会影响它。

        位置**仅在**其**自身元素**被从列表中删除时才失效。

        **经典陷阱：**将位置与索引混淆。位置是对容器（节点）的稳定引用，而非数字排名。

??? question "第7题 — Java 集合中的位置"
    Java 在其标准集合中不暴露位置，是因为设计疏忽，将在未来版本中修正。

    ??? success "答案"
        **假。** 这是一个**刻意的设计选择**，目的是保护不变量。

        如果 Java 暴露了内部节点（`Position`），用户可能会：

        - 保留对已删除节点的引用
        - 直接修改 `next`/`prev` 链接
        - 破坏数据结构

        Java 更倾向于暴露**迭代器**（修改后失效）而非持久位置。这是灵活性与安全性之间的权衡。

        当**控制**运行环境且需要在已知位置进行 O(1) 插入/删除时，位置列表非常有用。

??? question "第8题 — Java 的 Stack 类"
    `java.util.Stack` 类推荐用于在现代代码中实现栈。

    ??? success "答案"
        **假。** `java.util.Stack` 是一个**遗留**类（继承自 Java 1.0），存在以下几个问题：

        1. 它继承自 `Vector`，一个不以 LIFO 语义为中心的遗留 API
        2. 它暴露了违反 LIFO 原则的 `Vector` 方法（`add(index, element)`、`remove(index)`）

        **官方推荐**（Javadoc）：

        ```java
        // 避免使用
        Stack<String> stack = new Stack<>();

        // 推荐使用
        Deque<String> stack = new ArrayDeque<>();
        stack.push("A");
        stack.pop();
        ```

        `ArrayDeque` 更快且严格遵守栈接口。

??? question "第9题 — Deque 作为通用结构"
    `Deque`（双端队列）可以高效地同时模拟 `Stack` 和 `Queue`。

    ??? success "答案"
        **真。** `Deque` 允许在**两端**以 O(1) 进行插入和删除，这足以实现两种结构：

        | 结构 | 操作 | 用 Deque 实现 |
        |------|------|---------------|
        | **Stack**（LIFO） | `push(e)` | `addFirst(e)` |
        | | `pop()` | `removeFirst()` |
        | **Queue**（FIFO） | `enqueue(e)` | `addLast(e)` |
        | | `dequeue()` | `removeFirst()` |

        所有这些操作使用 `ArrayDeque` 都是 **O(1)**。

        这也是 Java Javadoc 推荐将 `ArrayDeque` 同时用于栈（`push`/`pop`）和队列（`offer`/`poll`）的原因：

        ```java
        Deque<String> stack = new ArrayDeque<>();  // 作为栈
        Deque<String> queue = new ArrayDeque<>();  // 作为队列
        ```

        **关键点：** `Deque` 是栈和队列的**泛化**。若一个结构允许在两端操作，它可以限制为只用一端（栈），或用一端输入、另一端输出（队列）。

#### C组 — 队列与优先级

??? question "第10题 — 最小堆中第3小元素的位置"
    在一个有 n 个元素（n ≥ 7）的最小堆中，**假设键/优先级互不相同**，第3小的元素必定位于深度1（即根的子节点）。

    ??? success "答案"
        **假。** 第3小的元素可能位于深度1**或**深度2。

        （使用的假设：优先级全部不同，如题目所述。）

        堆不变量保证每个父节点 ≤ 其子节点。因此：

        - **第1小**在根节点（深度0）
        - **第2小**是根的某个子节点（深度1）
        - **第3小**可能是：
            - 根的**另一个子节点**（深度1），**或者**
            - 根的**孙节点**（深度2），若根的两个子节点都较大

        ```
        第3小位于深度2的示例：

              1               数组：[1, 10, 5, 20, 15, 2, 8]
            /   \
          10     5
         / \   / \
        20 15 2   8    ← 2 是第3小，位于深度2！
        ```

        **一般规律：** 最小堆中第 k 小的元素可能位于 0 到 k−1 的任意深度。

        **经典陷阱：** 认为堆"几乎已排序"。唯一的保证是父节点 ≤ 子节点，兄弟节点之间没有关系。

??? question "第11题 — 最小堆的前序遍历"
    对最小堆进行前序（preorder）遍历，总是以非递减顺序列出键。

    ??? success "答案"
        **假。** 前序遍历的顺序为：根节点，然后左子树，然后右子树。堆性质（父节点 ≤ 子节点）**不**保证前序遍历时获得非递减顺序。

        反例：

        ```
              1
            /   \
           3     2
          / \
         5   4

        前序遍历：1, 3, 5, 4, 2
        ```

        得到的顺序是 1, 3, 5, 4, **2** — 不是非递减的，因为 2 < 4 且 2 < 5。

        **为什么？** 堆只保证每个父节点 ≤ 其子节点（**垂直**关系）。以下之间没有任何保证：

        - 兄弟节点（3 与 2）
        - 不同子树的节点（5 与 2）

        能给出有序中序遍历的是 **BST**（二叉搜索树），而非带前序遍历的堆。

        **经典陷阱：** 将堆性质与 BST 性质混淆。堆**不是**已排序的——它只是"部分有序"的。

??? question "第12题 — 堆中第二小元素的位置"
    在最小堆中，第二小的元素总是位于数组的索引1处。

    ??? success "答案"
        **假。** 第二小的元素位于索引1**或**索引2（根的两个子节点之一）。

        堆不变量只保证**每个父节点 ≤ 其子节点**。子节点之间（索引1和索引2）没有任何顺序关系。

        ```
        第2小在索引2处的有效堆：

              1           数组：[1, 5, 2, 7, 8, 3, 4]
            /   \
           5     2   ← 2 是第2小，位于索引2
          / \   / \
         7   8 3   4
        ```

        **经典陷阱：** 认为堆是已排序的。只有父子关系是有保证的。

??? question "第13题 — 堆与二叉搜索树"
    二叉堆和二叉搜索树（BST）具有相同的顺序性质。

    ??? success "答案"
        **假。** 顺序性质从根本上是不同的：

        | 性质 | 堆（最小） | BST |
        |------|-----------|-----|
        | 关系 | 父节点 ≤ 子节点 | 左 < 父 < 右 |
        | 最小值 | 根节点（O(1)） | 最左节点（O(h)） |
        | 按键搜索 | O(n) | O(h)，若平衡则 O(log n) |
        | 结构 | 完全树（数组） | 形状可变 |

        ```
              堆                    BST
               2                       5
             /   \                   /   \
            5     3                 3     7
           / \                     / \
          7   8                   2   4

        堆：5 > 3 但 5 在左边（合法）
        BST：左 < 父 < 右（始终如此）
        ```

        **非常常见的经典陷阱：** 混淆这两种结构。堆**不是** BST！

#### D组 — 图

??? question "第14题 — 树与图"
    每棵树都是图，但并非每个图都是树。

    ??? success "答案"
        **真。** 树是带有额外约束的图的特例：

        **树的定义**：连通且无环的图。

        - **连通**：任意一对顶点之间存在路径
        - **无环**：没有环

        派生性质（对于有 n 个顶点的树）：

        - 恰好有 n-1 条边
        - 每对顶点之间只有一条路径

        ```
              树                  图（非树）
                A                    A
               /|\                  /|\
              B C D                B-C-D
                                    \_/
                                  （有环！）
        ```

        **注意：** 在图论中，我们讨论无根树。在数据结构中，我们通常使用有根树（指定根节点）。

??? question "第15题 — 矩阵与邻接表"
    对于有 1000 个顶点和 3000 条边的图，邻接矩阵比邻接表使用更少的内存。

    ??? success "答案"
        **假。** 计算如下：

        **邻接矩阵**：

        - 大小：V × V = 1000 × 1000 = **1,000,000 个条目**
        - 即使对于稀疏图，所有单元格都存在

        **邻接表**：

        - 每条边出现在 2 个列表中（若为无向图）：3000 × 2 = **6,000 个条目**
        - 加上 V = 1,000 个列表头

        比率：1,000,000 / 6,000 ≈ **矩阵内存多 166 倍！**

        **实用规则**：

        - **稠密**图（E ≈ V²）→ 矩阵
        - **稀疏**图（E << V²）→ 邻接表

        这里，E = 3,000，V² = 1,000,000，所以 E << V²：图是稀疏的。

        **经典陷阱：** 默认使用矩阵。始终分析密度！

??? question "第16题 — 最大边数"
    有 n 个顶点的无向图最多可以有 n(n-1) 条边。

    ??? success "答案"
        **假。** 对于简单无向图（无自环或多重边），最大值为 **n(n-1)/2**。

        **无向图**：边 {u, v} 与 {v, u} 相同。

        - 可能的顶点对数：C(n,2) = n(n-1)/2

        **有向图**：弧 (u, v) 与 (v, u) 不同。

        - 可能的弧数（无自环）：n(n-1)

        | 类型 | 最大边/弧数 |
        |------|-----------|
        | 简单无向图 | n(n-1)/2 |
        | 简单有向图 | n(n-1) |
        | 带自环 | 在上述值上加 n |

        **经典陷阱：** 忽略有向与无向的区别。这使最大边数相差 2 倍。

??? question "第17题 — 边列表与邻域"
    在边列表表示中，操作 `incidentEdges(v)`（列出与 v 关联的边）的时间复杂度为 O(deg(v))。

    ??? success "答案"
        **假。** 在边列表中，`incidentEdges(v)` 需要**遍历所有边**才能找到与 v 关联的边，时间复杂度为 **O(m)**，其中 m 是边的总数。

        这是边列表相对于邻接表的主要弱点：

        | 操作 | 边列表 | 邻接表 |
        |------|-------|-------|
        | `incidentEdges(v)` | **O(m)** | **O(deg(v))** |
        | `areAdjacent(v, w)` | **O(m)** | **O(min(deg(v), deg(w)))** |
        | `insertEdge(e)` | **O(1)** | **O(1)** |
        | `removeEdge(e)` | **O(1)** | **O(1)** |
        | 空间 | O(n + m) | O(n + m) |

        边列表是最**简单**但邻域查询效率最低的结构。当主要需要遍历所有边时它很有用。

        **经典陷阱：** 混淆边列表和邻接表。边列表**不**按顶点存储边，而是存储在全局集合中。

??? question "第18题 — 带连通分量的最大边数"
    一个有 12 个顶点和 3 个连通分量的简单无向图最多可以有 45 条边。

    ??? success "答案"
        **真。** 为了最大化恰好有 k 个连通分量时的边数，需要**将顶点集中**在一个分量中，让其他分量尽可能小（每个只有 1 个顶点）。

        n = 12 个顶点，k = 3 个分量：

        - 将 **10 个顶点**放入一个分量（完全图）：C(10, 2) = 10 × 9 / 2 = **45 条边**
        - 在另外 2 个分量中各放 **1 个顶点**：每个 **0 条边**

        最大总数 = **45 条边** ✓

        **为什么这种分配是最优的？** 若更均匀地分配，例如 (4, 4, 4)：

        - C(4,2) × 3 = 6 × 3 = **18 条边** — 远少于 45！

        **一般公式：** 对于 n 个顶点和 k 个分量，最大边数为 C(n−k+1, 2) = (n−k+1)(n−k) / 2。

        验证：(12−3+1)(12−3) / 2 = 10 × 9 / 2 = 45 ✓

        **经典陷阱：** 认为均匀分配可以最大化边数。恰恰相反——函数 C(n, 2) 是凸函数，集中顶点能产生更多边。

### 第2节 — 比较型选择题

??? question "第1题 — 复杂度表格"
    补全 n 个元素列表的复杂度表格：

    | 操作 | ArrayList | LinkedList | 位置列表* |
    |------|-----------|------------|----------|
    | `get(k)` | ? | ? | ? |
    | `add(0, e)` | ? | ? | ? |
    | `add(k, e)` （中间） | ? | ? | ? |
    | `remove(position)` | ? | ? | ? |

    *预先已获取位置

    ??? success "答案"
        | 操作 | ArrayList | LinkedList | 位置列表* |
        |------|-----------|------------|----------|
        | `get(k)` | **O(1)** | **O(n)** | **O(n)** |
        | `add(0, e)` | **O(n)** | **O(1)** | **O(1)** |
        | `add(k, e)` | **O(n)** | **O(n)** | **O(1)*** |
        | `remove(position)` | **O(n)** | **O(1)*** | **O(1)** |

        *已知位置/迭代器时

        **关键点：**

        - `ArrayList` 在索引访问上表现出色，但插入/删除（移位）代价较高
        - `LinkedList` 访问为 O(n)，但**若已有位置**，插入/删除为 O(1)
        - **保留位置时**，位置列表兼具两者的优点

??? question "第2题 — 图的表示方法"
    一个交通网络有 **500 个站点**和 **800 条双向连接**。需要频繁列出给定站点的所有邻近站点，并检查两个站点是否直接相连。

    哪种表示方法最合适？

    - [ ] A) 边列表（edge list）
    - [ ] B) 邻接矩阵

??? question "第3题 — 复杂度分析"
    ```java
    void removeNegatives(List<Integer> list) {
        for (int i = 0; i < list.size(); i++) {
            if (list.get(i) < 0) {
                list.remove(i);
                i--;
            }
        }
    }
    ```

    若 `list` 是有 n 个元素（其中 k 个为负数）的 `LinkedList`，时间复杂度是多少？

    - [ ] A) O(n)
    - [ ] B) O(n + k)
    - [ ] C) O(n²)
    - [ ] D) O(nk)

    ??? success "答案"
        **C) O(n²)**

        分析循环中每个操作：

        - `list.get(i)`：在 LinkedList 中为 **O(i)**（从开头或末尾遍历）
        - `list.remove(i)`：查找 **O(i)** + 删除 O(1)

        循环执行 n 次（减去删除次数，但取 n 作为上界）。

        总代价：Σ O(i)，i 从 0 到 n ≈ O(n²)

        **为什么不是 O(nk)？** 即使是对正数元素的 `get(i)` 也要花费 O(i)。不仅仅是 k 次删除代价高昂。

        **最优解**：使用迭代器！

        ```java
        void removeNegatives(List<Integer> list) {
            Iterator<Integer> it = list.iterator();
            while (it.hasNext()) {
                if (it.next() < 0) {
                    it.remove();  // O(1)，因为迭代器已有位置
                }
            }
        }
        ```

        使用迭代器的复杂度：**O(n)**。

??? question "第7题 — 撤销/重做系统"
    您正在实现一个具有以下约束的撤销（Undo）系统：

    - 无限次撤销
    - 每个操作撤销后可以"重放"（Redo）
    - 撤销后执行新操作会清除重做历史

    所需的最小结构是什么？

    - [ ] A) 一个栈
    - [ ] B) 两个栈
    - [ ] C) 一个 Deque
    - [ ] D) 一个位置列表

    ??? success "答案"
        **B) 两个栈**

        经典模式使用两个栈：

        - **undoStack**：已执行的操作（LIFO — 最后一个操作 = 第一个被撤销）
        - **redoStack**：已撤销的操作（LIFO — 最后撤销的 = 第一个被重做）

        ```java
        class UndoManager {
            Deque<Action> undoStack = new ArrayDeque<>();
            Deque<Action> redoStack = new ArrayDeque<>();

            void doAction(Action a) {
                a.execute();
                undoStack.push(a);
                redoStack.clear();  // 新操作清除重做历史
            }

            void undo() {
                if (!undoStack.isEmpty()) {
                    Action a = undoStack.pop();
                    a.reverse();
                    redoStack.push(a);
                }
            }

            void redo() {
                if (!redoStack.isEmpty()) {
                    Action a = redoStack.pop();
                    a.execute();
                    undoStack.push(a);
                }
            }
        }
        ```

        **为什么不用 Deque？** Deque 技术上可以工作，但没有任何优势，概念上也不够清晰。两个显式栈使意图一目了然。

??? question "场景1 — 物联网传感器网络"
    **背景**：一个由 200 个环境传感器组成的网络。传感器通过无线电通信（有限范围）相互通信。网络有约 600 条双向链路。

    **所需操作**：

    1. 添加/删除传感器（少见：维护）
    2. 当传感器更改范围时添加/删除链路（偶尔）
    3. 列出网络中所有链路以计算总维护成本（频繁）
    4. 查找传感器的所有邻居以进行数据路由（非常频繁）

    **问题**：

    1. 对于操作3（列出所有链路），哪种表示方法最自然？复杂度是多少？
    2. 对于操作4（查找邻居），比较三种表示方法（边列表、邻接表、矩阵）。哪种最高效？
    3. 可以组合两种表示方法吗？权衡是什么？
    4. 该图是稠密图还是稀疏图？请说明理由并推断应避免哪种表示方法。

    ??? success "答案"
        **1. 列出所有链路——边列表：**

        **边列表**最适合遍历所有边：

        - 每条边是集合中存储的一个对象
        - 遍历：**O(m)** — 直接遍历列表

        在教材模型（第14.2节）中，也可以通过维护全局边集合，以 **O(m)** 的代价为其他表示方法暴露 `edges()`。

        没有这个辅助集合的话，则退回到：

        - 邻接表：O(n + m)，需处理重复
        - 矩阵：O(n²) 扫描矩阵

        ```
        边列表：
        [(A,B), (A,C), (B,D), (C,D), (D,E), ...]
        → 直接以 O(m) 遍历
        ```

        ---

        **2. 查找邻居——邻接表：**

        | 表示方法 | `incidentEdges(v)` | 此网络的代价 |
        |---------|-------------------|-----------|
        | 边列表 | O(m) | 每次查询 O(600) |
        | 邻接矩阵 | O(n) | O(200) |
        | **邻接表** | **O(deg(v))** | 平均 **O(6)** |

        对于此操作，邻接表比边列表**高效 100 倍**，因为平均度数为 2m/n = 1200/200 = 6。

        ---

        **3. 组合表示方法：**

        是的，可以**同时维护两种表示方法**：

        - **边列表**用于操作3（全局边遍历）
        - **邻接表**用于操作4（快速邻域查询）

        **权衡**：

        | 方面 | 单一结构 | 两种结构 |
        |------|---------|---------|
        | 空间 | O(n + m) | O(n + m) × 2 |
        | 插入边 | O(1) | O(1) × 2 次操作 |
        | 一致性 | 自动 | 必须保持两者同步 |

        若两种操作都很频繁，额外开销是可以接受的。这也是教材（第14.2节）推荐的方法。

        ---

        **4. 稠密还是稀疏？**

        - n = 200，m = 600
        - 最大边数（无向）：n(n-1)/2 = 19,900
        - 比率：600 / 19,900 ≈ **3%** → **稀疏图**

        **应避免的表示方法**：**邻接矩阵**，它需要 200² = 40,000 个条目，而实际只有 600 条边（内存多用 66 倍）。

    一个地区电网需要管理：

    **实体**：

    - **节点**：500 个点（发电站、变电站、变压器、消费点）

    3. **故障**：删除故障线路并验证网络是否保持连通（偶尔）
    4. **扩展**：在两个节点之间添加新线路（少见）

    **问题1**：主要表示方法的选择

    比较三种表示方法（边列表、邻接表、矩阵）对此网络的适用性。哪种最适合作为主要结构？

    **问题2**：线路属性的存储

    每条线路都有属性（容量、成本、当前负载）。如何在每种表示方法中存储这些属性？

    **问题3**：成本计算操作

    对于操作2，在主要结构之外额外维护一个边列表是否有利？请说明理由。

    **问题4**：故障后的连通性检测

    删除一条线路后，如何验证网络仍然是连通的？哪种表示方法有助于此验证？

    ??? success "答案"
        **问题1：表示方法的选择**

        | 标准 | 边列表 | 邻接表 | 矩阵 |
        |------|-------|-------|------|
        | 空间 | O(n + m) = 1,700 | O(n + m) = 1,700 | O(n²) = 250,000 |
        | 操作1：节点的邻居 | O(m) = O(1200) | **O(deg(v))** ≈ O(5) | O(n) = O(500) |
        | 操作2：所有线路（`edges()`） | **O(m)** = O(1200) | **O(m)** = O(1200) | **O(m)** = O(1200) |
        | 操作3：删除线路（`removeEdge(e)`） | O(1)* | O(1)* | O(1) |
        | 操作4：添加线路 | O(1) | O(1) | O(1) |

        **邻接表**是最佳主要结构，因为操作1（最频繁）为 O(deg(v)) 而非 O(m)。

        该图是稀疏的：m = 1,200 vs n² = 250,000，因此应避免使用矩阵。

        *注意（教材14.2）*：
        - `edges()` 的 O(m) 代价假设在主要表示方法之外维护了全局边集合。
        - `removeEdge(e)` 的 O(1) 代价假设已拥有对该边的引用。

        ---

        **问题2：属性的存储**

        - **边列表**：每个 Edge 对象直接存储其属性——这是最自然的方式。

        ```java
        class Edge {
            Vertex u, v;
            double capacity;
            double cost;
            double currentLoad;
        }
        ```

        - **邻接表**：邻居列表中的每个条目必须引用 Edge 对象（或复制数据）。

        ```
        A → [(B, edge1), (D, edge2)]  // 引用 Edge 对象
        ```

        - **矩阵**：属性存储在矩阵单元格中，而非简单的布尔值。

        ```
        M[A][B] = Edge(capacity=100, cost=50, load=75)
        ```

        **边列表对于存储属性最为自然。** 这是该表示方法的一个关键优势。

        ---

        **问题3：额外维护边列表是否有利？**

        **是的**，这是有利的。仅使用邻接表时，计算总成本需要：

        ```
        对每个顶点 v：
            对 v 的每条关联边：
                累加成本
        ```

        问题：在无向图中，每条边被计算**两次**（每个端点各一次）。需要除以 2 或标记已访问的边。

        使用**辅助边列表**：

        ```
        total_cost = 0
        对边列表中的每条边 e：
            total_cost += e.cost
        ```

        简单、直接、无重复。复杂度：**O(m)**。

        **权衡**：添加/删除边时需维护两个结构的一致性。每次修改操作的额外代价：O(1)。

        ---

        **问题4：连通性验证**

        删除边后，通过从任意顶点进行**遍历**（BFS 或 DFS）来验证连通性：

        - 若遍历访问了**所有 n 个顶点** → 网络仍然连通
        - 否则 → 删除操作断开了网络

        **复杂度**：遍历为 O(n + m)。

        **邻接表**有助于此验证，因为 BFS/DFS 遍历在每个顶点需要 `incidentEdges(v)`，使用邻接表为 O(deg(v))，而使用边列表为 O(m)。

        仅使用边列表时，遍历总代价为 O(n × m) — 太慢了。

        ```
        验证连通性的 BFS 遍历：

        visited = {start_vertex}
        queue = [start_vertex]
        while queue is not empty:
            v = queue.dequeue()
            for each neighbor w of v:    ← 使用邻接表为 O(deg(v))
                if w not in visited:
                    visited.add(w)
                    queue.enqueue(w)
        return |visited| == n
        ```

??? question "练习B — 实现"
    ```java
    /**
     * 给定一个整数数组和整数 k，
     * 返回 k 个最大元素（顺序任意）。
     *
     * 约束：复杂度 O(n log k)，而非 O(n log n)。
     *
     * 提示：使用什么类型的堆，大小是多少？
     */
    public static int[] topK(int[] array, int k) {
        // 待实现
    }
    ```

    ??? success "答案"
        **核心思路：** 使用大小为 k 的**最小堆**。

        - 遍历数组
        - 若堆中元素少于 k 个，则添加
        - 否则，若当前元素 > 堆的最小值，则替换最小值

        最终，堆中恰好包含 k 个最大元素。

        ```java
        public static int[] topK(int[] array, int k) {
            if (k <= 0) return new int[0];
            if (k >= array.length) return array.clone();

            // 最小堆：k 个最大值中最小的在根节点
            PriorityQueue<Integer> minHeap = new PriorityQueue<>(k);

            for (int num : array) {
                if (minHeap.size() < k) {
                    minHeap.offer(num);
                } else if (num > minHeap.peek()) {
                    minHeap.poll();   // 删除最小值
                    minHeap.offer(num);  // 添加新值
                }
            }

            // 转换为数组
            int[] result = new int[minHeap.size()];
            for (int i = 0; i < result.length; i++) {
                result[i] = minHeap.poll();
            }
            return result;
        }
        ```

        **复杂度分析：**

        - 数组遍历：n 次迭代
        - `offer` / `poll`：O(log k)，`peek`：O(1)
        - 堆操作次数：最多 2n 次（每个元素的 offer + poll）
        - **总计：O(n log k)**

        **为什么用最小堆而不是最大堆？**

        使用大小为 k 的最小堆：

        - 根节点是 **k 个最大值中最小的**（"阈值"）
        - 每个元素与阈值的比较为 O(1)
        - 若更大，则弹出阈值并插入新值

        使用最大堆时，无法高效访问最小值，因此没有阈值。

        **与排序的比较：**

        | 方法 | 复杂度 | n=100万，k=10 时 |
        |------|-------|----------------|
        | 完全排序 | O(n log n) | ~2000 万次操作 |
        | 大小为 k 的最小堆 | O(n log k) | ~330 万次操作 |

        对于此情况，堆的效率**高出 6 倍**。

#### 决策树：选择数据结构

```

│   └─► 插入后优先级会变化吗？
│       ├─► 是 → 可适应优先队列（堆 + 定位器）
│       └─► 否 → 简单堆
│
├─► LIFO（后进先出）
│   └─► 栈（使用 ArrayDeque）
│
├─► FIFO（先进先出）
│   └─► 队列（ArrayDeque 或 LinkedList）
│
└─► 实体之间的关系
    └─► 图
        └─► 主要操作？
            ├─► 遍历所有边 → 边列表
            ├─► 邻域查询 → 邻接表
            └─► O(1) 验证邻接性 → 邻接矩阵（若图稠密）
```

#### 经典陷阱 — 总结

| 陷阱 | 实际情况 |
|------|---------|
| LinkedList 插入总是更快 | 仅在已有位置时！`get(i)` = O(n) |
| 堆 = 有序数组 | 错！唯一保证：父节点 ≤ 子节点 |
| `java.util.Stack` = LIFO 的现代选择 | 遗留类：优先使用 `Deque` / `ArrayDeque` |
| 位置 = 稳定的索引 | 位置在**其自身**元素删除后失效 |
| 边列表 = 邻域查询快 | 错！`incidentEdges(v)` = O(m)，而非 O(deg(v)) |
| 矩阵 = 图的默认选择 | 稀疏图会浪费 O(V²) 内存 |
| 均摊复杂度 = 每次操作 | 错，这是 n 次操作的平均值 |
